# タスク一覧

[決定事項](decisions.md)

実行モード・優先順位・終了条件はリポジトリ直下の AGENTS.md を正本とする。「成果物」は両モード共通の要件、「個別実行時」はユーザーが1項目ずつ進める場合だけの手順とする。一括仮作成では、選択や承認をAIの仮決めに置き換え、各成果物を最後まで作成する。AIの仮作成だけではチェックOFFを保つ。チェックONは、ユーザーがその項目を承認・完了とした場合だけにする。仮作成した成果物への相対リンクは各項目の直下に掲載する。一括仮作成の再開時は、チェック状態ではなく、リンク先の成果物と内容を確認して不足分だけを作る。

- [ ] 事業を決める
  - 成果物：事業内容・商圏・ユーザーが指定した条件を決定事項に記録する。商圏の指定がなければ京都市を仮採用する。AGENTS.mdの「事業フォルダの命名と変更」に従い、管理用フォルダ名を事業内容を表す名前へ一度変更する。
  - 個別実行時：ユーザーがやりたい事業を端的に入力する。商圏が未確定なら「商圏は京都市でいいですか？」と確認し、修正があれば反映する。

- [ ] 事業名を決める
  - 成果物：事業内容に合う名前の候補を15個程度作り、採用する仮事業名を記録する。SEOやMEOも意識する。
  - 個別実行時：AIが候補を提示し、ユーザーが最終的な仮事業名を決める。

- [ ] ロゴを作る
  - 成果物：ロゴ画像を作成する。基本的に事業名を洗練されたフォントで書けばよい。
  - 個別実行時：AIが画像を作成し、ユーザーが修正できる。

- [ ] メールアドレスを決める
  - 成果物：事業用メールアドレスとして使う文字列を決める。基本的に事業名.official@gmail.comとする。シミュレーションでは実際のアカウント作成はしない。
  - 個別実行時：AIがアイデアを提示し、ユーザーと文字列を決める。

- [ ] 提供する商品orサービスを決め、料金表を作る
  - 成果物：提供する商品・サービスと顧客向けの料金表を完成させる。周辺地域の競合料金を確認し、それを踏まえて料金設定する。確認した競合料金もユーザーに示す。
  - 個別実行時：AIが商品・サービスを提案し、ユーザーが修正・承認した後、料金表を完成させる。

- [ ] 必要な道具を洗い出す
  - 成果物：事業開始・サービス提供に必要な道具、設備、ソフト等を、過剰にならない範囲でチェックボックス付きの一覧にする。
  - 個別実行時：ユーザーが修正・追加・削除できる。

- [ ] 必要なスキル・知識を洗い出す
  - 成果物：事業を実際に提供するために必要なスキル・知識を、過剰にならない範囲で箇条書きにする。
  - 個別実行時：ユーザーが修正・追加・削除できる。

- [ ] 商圏（母数）から顧客数を推定する
  - 成果物：対象市場の母数を調査・推定し、現実的に獲得できそうな顧客数を試算する。ターゲット数、セグメンテーション数、競合の数や規模を把握して試算する。適切な算出方法が複数あれば複数の切り口を用い、必要な場合だけフェルミ定数を使う。
  - 個別実行時：AIが試算を提示し、ユーザーが修正箇所を指摘できる。

- [ ] 初期の顧客をどう獲得するかニッチ戦略を決める
  - 成果物：初期の顧客を獲得するためのニッチ戦略を決め、内容を記録する。
  - 個別実行時：AIが提案して検討を促し、ユーザーが決めて入力する。

- [ ] 集客方法を決める（オーガニック？メール営業？）
  - 成果物：この事業に合う集客手段を比較し、採用する方法を記録する。
  - 個別実行時：主にユーザーが決めて入力する。

- [ ] 1ヶ月あたりの売上を想定する
  - 成果物：想定顧客数と料金をもとに、1ヶ月あたりの売上を試算する。
  - 個別実行時：AIが試算を提示し、ユーザーが修正できる。

- [ ] 1ヶ月あたりの費用を想定する
  - 成果物：事業を維持するために毎月発生するランニングコストを試算する。
  - 個別実行時：ユーザーが修正・追加・削除できる。

- [ ] 1ヶ月あたりの利益と1件あたりの利益を想定する
  - 成果物：想定売上と費用をもとに、1ヶ月あたりの利益と1件あたりの利益を試算する。
  - 個別実行時：AIが試算を提示し、ユーザーが修正できる。

- [ ] 初期費用を想定する
  - 成果物：事業開始までに必要な費用を試算する。
  - 個別実行時：AIが試算を提示し、ユーザーが修正できる。

- [ ] ホームページを作る
  - 成果物：画像生成でサイトのデザインを作り、実際に閲覧できるHPまで完成させる。必要な画像はネット上のフリー素材かAIの画像生成で用意する。SEO・MEOを意識し、開業前ではなく、すでに営業している事業を想定したHPにする。作成したHPのGitHub PagesのURLをユーザーに示す。
  - 個別実行時：まず画像生成したデザインをユーザーに見せ、OKが出てからHPを実装する。

- [ ] 予約フォームを作る
  - 成果物：事業に必要な予約項目を仮決めし、予約フォームを作る。開業前ではなく、すでに営業している事業を想定したフォームにする。作成したフォームのGitHub PagesのURLをユーザーに示す。
  - 個別実行時：AIがフォームを作成し、必要があればユーザーが修正を指示する。

- [ ] Googleビジネスプロフィールを作る
  - 成果物：実際のGoogleビジネスプロフィールを想定して掲載内容を仮作成する。必要な画像はフリー素材かAIの画像生成で用意し、説明文はMEOを意識する。シミュレーションなので実際の申請はしない。
  - 個別実行時：AIが掲載内容を提示し、ユーザーが修正できる。

- [ ] 必要なSNSを作る
  - 成果物：必要なSNSを判断し、実際のアカウントを想定したプロフィール・投稿内容等を作成する。
  - 個別実行時：採用するSNSをユーザーが承認してから、プロフィール・投稿内容等を作成する。
